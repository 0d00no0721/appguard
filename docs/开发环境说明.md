# 开发与验证环境说明

> 这份文档记录**实测结论**，不是推测。后面所有"能不能验证"的判断都以它为准。

## 0. ★ 两种会话模式，能力完全不同（2026-10-17 下午实测更正）

同一台机器上，DSH 会话的**文件策略**会改变系统通道的可用性，实测对照：

| 通道 | 受限模式（read-only / workspace-write） | **danger-full-access** |
|---|---|---|
| 进程可见数 | 25~27 | **359** |
| `tasklist` / WMI / CIM | 拒绝访问 | 正常 |
| 计划任务（`Get-ScheduledTask`） | 0 条 | **220 条** |
| 命名管道客户端连接 | `拒绝访问(5)` | **正常** |
| 写入 `tmp*` 目录 | 拒绝 | 正常 |

⇒ **代码必须两种模式都能跑**（已实现：管道不可用自动降级回环 TCP；进程/任务通道缺失时降级为
"能拿多少算多少"并诚实报告 `health=degraded`）。
**受限模式下的所有"看不到"结论都不要当成机器事实** —— 例如"本机只有 27 个进程"是错的。

## 1. 目标运行环境（工具最终跑在哪）

| 项 | 值 |
|---|---|
| 系统 | Windows 11（内核 10.0.26100，来自系统事件与 `ntdll.dll` 版本） |
| 用户 | `<计算机名>\<用户名>`，桌面会话 session 1 |
| Python | **3.12.10** @ `<Python 安装目录>\python.exe` |
| 已装依赖 | `pywin32`、`Pillow`、`PyYAML`、`tomllib`(stdlib) |
| **未装** | `psutil`、`wmi`、`pystray` ⇒ **核心不得依赖它们** |

技术选型据此确定：**stdlib + ctypes + pywin32**，零额外安装即可运行。

## 2. DSH 执行沙箱的限制（★ 重要）

本会话里跑的 `pwsh` / `python` 命令虽然身份与会话都正常（`whoami` = `<计算机名>\<用户名>`、`SessionId` = 1、`UserInteractive` = True），
但**带受限令牌**，导致部分系统通道不可用：

| 通道 | 沙箱内实测 | 影响 |
|---|---|---|
| `toolhelp32`（`list_raw_processes`） | 只见 **25~27** 个进程 | **无法验证覆盖率**；真实桌面会有 150~300 个 |
| `tasklist` / `Get-Process` | `Access denied` / 同样只有 25 个 | 同上 |
| `GetForegroundWindow` 归属 pid | 返回的 pid **不在可见集合里** | 前台判定在真机上才有效 |
| WMI COM（`SWbemLocator.ExecQuery`） | `拒绝访问` | 已改为不依赖 WMI |
| CIM（`Get-CimInstance Win32_Process`） | **0 行** | 同上 |
| 计划任务（`Schedule.Service` COM） | `系统找不到指定的路径` | 计划任务枚举在真机上才能验证 |
| 计划任务（`Get-ScheduledTask`） | **0 条** | 同上 |
| 计划任务（`schtasks`） | `ERROR: The system cannot find the path specified.` | 同上 |
| 注册表（服务/Run/卸载信息） | ✅ 正常 | 服务的配置信息走这条 |
| SCM 服务状态（`OpenSCManager`+`QueryServiceStatus`） | ✅ 正常（334 个服务） | 服务状态走这条 |
| `NtQueryInformationProcess(60)` 命令行 | ✅ 正常（96% 覆盖） | **命令行的主通道** |
| Authenticode / 文件版本信息 | ✅ 正常 | 厂商识别走这条 |
| `EnumWindows` 可见窗口 | ✅ 正常（9 个进程有窗口） | 活跃度判定可用 |

**结论：**
1. 采集层在**真实桌面 + 管理员权限**下会看到完整数据；
2. 在沙箱里只能验证「通道是否可用」，**不能验证「覆盖率与正确率」**；
3. 因此覆盖率类验收（接口规范 §10 的 C3/C4/C5）必须由用户在真机上跑 `guardctl doctor` 完成，
   沙箱内用**合成数据 + 单元测试**验证逻辑。

## 4. 已踩过的坑（写在这里避免重复踩）

| # | 现象 | 根因 | 处置 |
|---|---|---|---|
| 1 | `EnumServicesStatusEx` 抛 `TypeError: Objects of type 'int' can not be converted to Unicode` | pywin32 的 SWIG 绑定参数不兼容 | **不用它**：注册表取配置 + 逐个 `QueryServiceStatus` 取状态 |
| 2 | 服务状态全部 `unknown` | pywin32 `QueryServiceStatus` 返回 `(ServiceType, CurrentState, ...)`，**状态在索引 1**，索引 0 是类型（272） | `_extract_state()` 按"值必须是合法状态"判定次序 |
| 3 | 签名的 QQ.exe 被判成 `signed=False` | 中文系统下 `$s.Status` 是本地化文本（"有效"），不是 `"Valid"` | 改用 **`[int]$s.Status`**（0=Valid 2=NotSigned …） |
| 4 | ctypes 调用崩溃/错值 | 漏声明 `restype` 时指针被截断成 32 位 int（`GetSidSubAuthority` 等） | 文件顶部统一声明签名 |
| 5 | WMI 拿不到命令行 | 环境阻断 | 改用 **`NtQueryInformationProcess(ProcessCommandLineInformation=60)`**：只需 `PROCESS_QUERY_LIMITED_INFORMATION`，不读内存、不需要 WMI |
| 6 | 注册表里服务多出 80 多个 | `Services` 键下混有性能库等伪服务 | 过滤条件加**必须有 `ImagePath`** |
| 7 | `taskkill /T /F /PID` 返回 `ERROR: Access denied` | 受限环境下外部工具被拒 —— **即使目标是我们自己创建的子进程** | 主通道改为**原生 `TerminateProcess`**（`winapi.terminate_process` / `terminate_tree`），`taskkill` 仅作兜底；结束进程树用**后序遍历先子后父** |
| 8 | 「在用」判定过宽，清理候选恒为 0 | 把任何 `origin=user` 的进程都算在用；且候选集硬性要求 `origin ∈ {autostart,service,child_of_service}`，在父进程不可见时永远为空 | 「刚启动」叠加**时间窗**；`origin` 降级为**风险输入**而非硬过滤（接口规范 §5.2 已同步） |
| 9 | 服务拉起的进程被误判成"用户子进程" | 服务用 `CreateProcessAsUser` 在**用户会话**里创建进程 ⇒ 会话号是 1，父进程名也不在已知服务列表 | 新增判据：**父进程的可执行文件本身是某个服务的 `ImagePath`** ⇒ `origin=service`（雷电站例：`ld29297.exe` 的父进程 `ldplayerservice.exe`） |
| 10 | 卸载项的 `InstallLocation` 是 `E:\` | 直接采信会把整块盘的程序并进同一个软件 | `_is_plausible_root()` 拒绝盘符根/容器目录/Windows 目录 + 层级深度守卫 |
| 11 | `CreateNamedPipe` 报 `1314 客户端没有所需的特权` | 带强制标签 `S:(ML;;NW;;;ME)` 的 SDDL 需要 **`SeSecurityPrivilege`**；非管理员不持有 | 安全描述符按 **带标签 → 仅 DACL → 默认** 逐级降级，并把每次失败原因记进 `last_error` |
| 12 | 管道**建得成**，客户端 `CreateFile` 却报 `拒绝访问(5)` | **沙箱拦截命名管道客户端连接**（连同一进程、同一用户都拒） | 守护启动后**自检一次**（`probe_pipe`），不通过就**自动降级到回环 TCP + token**（`endpoint.json` 下发端点） |
| 13 | 管道起不来却完全没有提示（空转重试） | 重试循环里 `except Exception: continue` 把异常吞了 | 首次失败即写 stderr + 审计 `daemon.pipe_error`；`status.get.ipc` 暴露 `last_error` |
| 14 | `PermissionError` 写不进 `tempfile.mkdtemp()` 建的目录 | **沙箱禁止写入名字以 `tmp` 开头的目录**（`mkdtemp`/`TemporaryDirectory` 生成 `tmpXXXX`） | 测试改用固定工作目录（`tests/harness.py: work_dir()`，落在 `tests/.work/<name>`） |
| 15 | 程序直接装在安装目录根下时"归属"匹配失败（软件名退化成目录名） | `_is_ancestor()` 只认**严格**子目录，`exe_dir == install_dir` 时不匹配 | 改用 `_covers()`（**含相等**）——程序装在安装目录根下是最常见形态 |

## 5. 2026-10-18 改造新增的实测点

| # | 现象 | 根因/处置 |
|---|---|---|
| 16 | 服务进程的 exe 显示为 `%SystemRoot%\System32\...`，微软判定失败、软件名退化成 `System32` | 服务 `ImagePath` 可能带未展开环境变量（或 `\SystemRoot\` 前缀）。`inventory._norm()` 现在做 `expandvars` + `\SystemRoot` 展开；服务进程补全 exe 后重新读版本信息（否则厂商为空，WSL 等会被当第三方） |
| 17 | 广告弹窗出现时，软件被判“你在用”，清理候选变 0 | `_in_use_of()` 只把主程序/启动器/辅助的窗口算“在用”；ad/updater/telemetry/crash/installer 的窗口不算 |
| 18 | 计划刚生成就 `E_PLAN_STALE`（真实桌面每几秒有进程来去） | 执行时的失效校验改为只校验**本次选中的 PID**是否仍在候选池；全池指纹仅用于直接调用/测试 |
| 19 | 旧 `config.toml` 的 `kill_tree=true` 会让“按进程”变成“连树杀” | `load_config` 忽略该值并告警；按进程执行默认不连带子进程 |
| 20 | 旧 `never_touch_roles=["system","service"]` 会挡住“停第三方服务” | 加载时移除 `service` 并告警；微软服务由微软规则保护，关键服务由关键进程名保护 |

## 6. 2026-10-19 浏览器前端/启动器新增实测点

| # | 现象 | 根因/处置 |
|---|---|---|
| 21 | `msedge/chrome --headless --dump-dom` 或 `--screenshot` **一直不退出、没有输出** | 页面有长连接 SSE（`EventSource`），`load`/虚拟时间被挂住。改用 **Chrome DevTools Protocol**：`--remote-debugging-port` + WebSocket，`Page.navigate` → 等 6~9s → `Page.captureScreenshot` / `Runtime.evaluate`；开发脚本见 `tools/dev/cdp-shot.js`、`tools/dev/cdp-tour.js` |
| 22 | 启动器探测守护失败，**重复起第二个守护**（TCP 回退到另一个端口） | `--pipe-name` 传了裸名 `AppGuard.v1`，而 `IpcClient` 直接用该字符串 `CreateFile`（不补 `\\.\pipe\`）⇒ 每次连接空转 10s。启动器现在 `normalize_pipe_name()` 补全；同时守护写 `daemon.pid`，启动器发现 pid 存活就不再启动 |
| 23 | 网关 `/api/health` 慢到 10s 或超时 | 同 #22：`IpcBackend.probe()` 的 ping 连接空转。修法同上；健康检查现在毫秒级（实测 0.02s） |
| 24 | `GET /` 返回页面但 CSS/JS 404，页面是白板 | 静态页要求 `index.html + app.css + app.js` 三者齐全；缺任一文件时 `GET /` 回退 API 发现 JSON，`/api/health` 的 `frontend` 报 `partial`/`missing` 并列出缺失文件 |
| 25 | 用 `--app` 打开后出现第二个窗口 | 启动器先枚举窗口标题（`AppGuard ·` 前缀），有则 `ShowWindow + SetForegroundWindow`；没有才启动浏览器。Edge `--app` 复用现有配置/进程，**不要**加 `--user-data-dir` |
| 26 | 页面刷新后要重新带 token | 首次 `#token=` 读入 `sessionStorage` 并 `history.replaceState` 去掉 hash；刷新仍可用。换网关/重启后 token 变化，需用新 URL |
| 27 | `workspace-write` 沙箱下 Chrome headless 直接 `FATAL: mojo platform_channel 拒绝访问` | 沙箱阻止 Chrome 的跨进程通道；浏览器自动化验收需要 **`danger-full-access`**（或真机手动验收）。Chrome 报错不是页面问题 |
| 28 | 自动刷新整屏闪 | SSE `snapshot.updated`/`process.*` 原先触发 `refreshCurrent` → `#screen.innerHTML` 全量重建 + `.screen-inner > *` 入场动画。现改 `softRefresh` 只 patch 数据区域；动画只加 `.screen-inner.enter`（仅导航）。用 CDP `MutationObserver` 验收：`screenInner=0`、`animationstart=0` |
| 29 | 安装后仍然没有管理员守护 | 旧版只注册登录任务、不立即启动，也没停普通守护；现改为 stop → 注册 → `schtasks /run` → `wait_admin.py` 等 `elevated=true`。另有一键 UAC 的 `tools\AppGuard-admin.bat` |
| 30 | pythonw 下子进程 `print` 崩溃 / `guardctl stop` 没执行 | pythonw 的 `sys.stdout` 是 `None`；启动器统一用 `console_python()`（同目录 `python.exe`）spawn daemon/web/cli，不要直接用 `sys.executable` |
| 31 | 关闭 Edge 窗口后 AppGuard 还在后台 | 这是设计：`launcher.json` 默认 `close_action=tray`；要“关闭即退出”在托盘菜单改成“退出 AppGuard”，此时会停网关/守护并退出托盘 |
| 32 | `Get-Process` 看不到 `AppGuard · 总览` 主窗口标题 | Edge `--app` 窗口的主窗口标题不在主进程 `MainWindowTitle` 上；用 `EnumWindows`（`tools/appguard_launcher.py:window_list()`）检测，且窗口可能比启动日志晚数秒出现 |
| 33 | Edge 弹窗“现有实例正在以提升的权限运行” | 有一个 Edge 实例被管理员启动；普通用户再启动 Edge 会弹这个。**托盘/Edge 必须普通用户**：Inno 的 `[Run]` 用 `runasoriginaluser`；不要以管理员运行 `AppGuard.bat`/`AppGuard.exe`。点“是”可重启为普通权限（Edge 会恢复标签页） |
| 34 | 冻结版用 pystray 托盘卡住、setup 不回调 | PyInstaller windowed 下 pystray 的 hidden window 创建会阻塞；改用 `tools/win_tray.py`（ctypes `Shell_NotifyIcon`），冻结包不再包含 pystray/Pillow |
| 35 | pythonw/冻结版日志没写 | windowed 下 `sys.stdout=None`；`packaging/entry.py` 打开一个日志文件并复用同一句柄，**不要对同一文件二次 open**（Windows 共享冲突会 PermissionError） |

## 7. 真机验收清单（交给用户执行）

```powershell
# 在真实桌面、以管理员身份
python src\appguard\cli.py doctor        # 覆盖自检：进程数/服务数/WMI/任务计划/权限
python src\appguard\cli.py software      # L1：在用软件
python src\appguard\cli.py ps --explain  # L2：进程分类
python src\appguard\cli.py plan          # L3：清理计划（默认 dry-run）
```
